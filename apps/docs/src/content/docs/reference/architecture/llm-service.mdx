# LLM Service

Lingchu Bot ships a managed LLM runtime that owns Pydantic AI agents, normalizes agent responses into stable value objects, and isolates credentials and control-plane parameters from callers. The runtime is optional: when its dependencies or configuration are unavailable, non-AI bot services still start.

## Architecture

The LLM service lives under `services/llm/` and is split into focused modules.

| Module | Responsibility |
| --- | --- |
| `services/llm/runtime.py` | Managed lifecycle, profile cache, Pydantic AI `Agent` cache, stable `respond` / `stream` interface, hot reload |
| `services/llm/config.py` | Localstore-backed `llm.toml` parsing for the `[pydantic-ai]`, `[mcp]`, and `[observability]` sections |
| `services/llm/agent.py` | `MCPAgentRuntime` that drives one Pydantic AI `Agent` run over configured `MCPToolset`s |
| `services/llm/mcp.py` | `MCPRuntime` owning one `pydantic_ai.mcp.MCPToolset` per configured MCP server |
| `services/llm/mcp_lifecycle.py` | Managed lifecycle for the MCP Agent runtime (init / reload / shutdown) |
| `services/llm/capabilities.py` | Advisory, model-string-based capability probes with a process-level cache |
| `services/llm/security.py` | Bounded immutable data helpers, log redaction, and control-plane key detection |
| `services/llm/types.py` | Stable immutable value objects (`LLMProfile`, `LLMResponse`, `LLMEvent`, `LLMUsage`) |
| `services/llm/events.py` | Lossless projection of provider-native stream events into `LLMEvent` |
| `services/llm/observability.py` | Structured `LLMCallRecord` emission for call observability |

The public package `services/llm/__init__.py` re-exports the stable interface and lazily loads runtime-heavy symbols through `__getattr__` so importing the package never imports `pydantic_ai` or provider SDKs.

## Configuration

LLM configuration is loaded from `llm.toml` resolved through
`nonebot_plugin_localstore.get_plugin_config_file()`. AI features require an
operator-managed file with an explicit `[pydantic-ai]` section. Legacy
`[profiles]`, `[router]`, and `[eve]` sections are ignored with a deprecation
warning so operators can migrate incrementally.

### Pydantic AI configuration

The `[pydantic-ai]` section is validated by a strict Pydantic model
(`PydanticAIConfig` with `extra = "forbid"`).

```toml
[pydantic-ai]
model = "openai:gpt-5.2"                 # required, pattern: ^[\w.-]+:[\w./-]+$
api_key_env = "LINGCHU_AI_API_KEY"       # environment variable name (optional)
base_url = "https://api.openai.com/v1"   # optional provider base URL
timeout = 60.0                            # must be greater than zero
```

| Field | Default | Notes |
| --- | --- | --- |
| `model` | required | Must match `^[\w.-]+:[\w./-]+$`; the prefix selects the Pydantic AI provider (e.g. `openai:`, `anthropic:`, `google-gla:`, `google-vertex:`) |
| `api_key_env` | `None` | Name of the environment variable holding the API key; resolved lazily at first call |
| `base_url` | `None` | Optional provider base URL passed through to Pydantic AI as `model_settings["base_url"]` |
| `timeout` | `60.0` | Per-call timeout in seconds, passed through as `model_settings["timeout"]` |

The `[mcp]` table configures the explicit MCP Agent (see
[Explicit reviewed MCP Agent](#explicit-reviewed-mcp-agent)), and the
`[observability]` table toggles structured call records. There is no
`[profiles]`, `[router]`, or `[eve]` section any more; deployment-level LLM
fields are no longer a fallback source.

## Stable interface

The runtime exposes two stable operations on `LLMRuntime`:

- `respond(input, *, profile=None, **params) -> LLMResponse` — one normalized response
- `stream(input, *, profile=None, **params) -> AsyncIterator[LLMEvent]` — a lossless projection of the agent stream

Both resolve a profile, build a `pydantic_ai.Agent` (cached per
`(name, generation, api_key fingerprint)`), coerce the legacy input format
into a Pydantic AI user prompt and optional `message_history`, merge
non-control-plane `params` into `model_settings`, and delegate to
`agent.run()` / `agent.run_stream()`. The assembled `LLMResponse` always
carries `text`, `output`, `usage`, `request_id`, `model`, `backend` (always
`"pydantic_ai"`), and the Pydantic AI `raw` result object.

`Agent` construction uses `defer_model_check=True` so provider and API key
validation is deferred until the first `run` / `run_stream` call. This lets
the runtime be constructed before the referenced environment variable (for
example `OPENAI_API_KEY`) is provisioned in deployment.

### Legacy backend access

`LLMRuntime.openai(name=None)` and `LLMRuntime.litellm(name=None)` are
retained as deprecated stubs: both always raise `_WrongBackendError` (an
`LLMConfigurationError`). The OpenAI and LiteLLM backend classes have been
removed. Callers that previously reached for native SDK handles must now
either use the stable `respond` / `stream` interface or build their own
Pydantic AI `Agent` directly.

## Capability probing

`services/llm/capabilities.py` exposes advisory, model-aware probes through
`CapabilityRegistry.probe(profile, capability, *, backend)`. Probes return a
`CapabilityResult` with `support` set to one of:

- `supported` — the model string prefix is known to support the capability through Pydantic AI's provider integration
- `unsupported` — not emitted by the current heuristic (returned as `unknown` instead)
- `unknown` — the model string is not authoritative for the capability

Only `"web_search"` is supported. The probe is a pure heuristic over
`profile.model`: model strings starting with `openai:`, `anthropic:`,
`google-gla:`, or `google-vertex:` return `supported`; everything else
returns `unknown`. The `backend` parameter is retained for signature
compatibility with legacy callers (notably `contracts.py`) but is
intentionally ignored — Pydantic AI agents do not expose a uniform SDK probe
surface.

`unknown` never prevents a call. Results are cached per
`(profile.model, capability)` and invalidated by `invalidate_capability_cache()`
after a configuration reload.

## Error mapping

`_normalized_error()` in `runtime.py` maps exceptions raised by Pydantic AI
and the underlying provider SDKs to the project's `LLMError` hierarchy. Each
mapped error carries `backend="pydantic_ai"`, `model`, and (when available)
`status_code`, `request_id`, and a `retryable` hint.

| Source exception | Mapped error | Notes |
| --- | --- | --- |
| `pydantic_ai.exceptions.ModelHTTPError` (status 401, 403) | `LLMAuthenticationError` | Provider rejected credentials |
| `pydantic_ai.exceptions.ModelHTTPError` (status 429) | `LLMRateLimitError` | `retryable = True` |
| `pydantic_ai.exceptions.ModelHTTPError` (status 408, 504) | `LLMTimeoutError` | `retryable = True` |
| Other `ModelHTTPError` | `LLMProviderError` | Carries `status_code` |
| `asyncio.TimeoutError`, `TimeoutError` | `LLMTimeoutError` | `retryable = True` |
| `ImportError`, `ModuleNotFoundError` | `LLMDependencyError` | `pydantic-ai` missing or provider SDK not installed |
| `ModelAPIError`, `AgentRunError` | `LLMProviderError` | Generic agent / model failure |
| Exceptions whose type name contains `connect` / `connection` | `LLMConnectionError` | `retryable = True` |
| Any other exception | `LLMProviderError` | Fallback |

## Security

### Control-plane key rejection

`CONTROL_PLANE_KEYS` in `security.py` is a frozen set of keys that callers
must not pass through the stable interface. It covers credentials
(`api_key`, `access_token`, `azure_ad_token`), endpoints (`base_url`,
`api_base`, `azure_endpoint`, `organization`, `project`), transport
(`transport`, `http_client`, `client`), callbacks (`callback`, `callbacks`,
`success_callback`, `failure_callback`, `custom_logger`, `logger_fn`,
`loggers`), headers and query (`headers`, `extra_headers`, `default_headers`,
`query`, `extra_query`, `default_query`), retry control (`max_retries`,
`retry`, `retries`, `retry_config`, `retry_policy`, `retry_strategy`,
`num_retries`, `allowed_fails`, `fallbacks`, `context_window_fallbacks`,
`content_policy_fallbacks`), and `router` / `token`.

`LLMRuntime.respond()` and `LLMRuntime.stream()` raise
`_ControlPlaneParameterError` (an `LLMConfigurationError`) when any `**params`
key intersects `CONTROL_PLANE_KEYS`. Per-call `params` may still pass
provider-accepted model settings (for example `temperature`) — only the
control-plane keys listed above are rejected.

### No automatic tool execution in `LLMRuntime`

`LLMRuntime.respond()` and `LLMRuntime.stream()` never execute tool calls.
The stable interface is tool-free; tool execution is the responsibility of
the explicit `MCPAgentRuntime` described below.

## Explicit reviewed MCP Agent

MCP is available only through `MCPAgentRuntime`; ordinary `LLMRuntime.respond()`
and `stream()` remain tool-free. The feature is disabled by default and
configured only in `llm.toml`:

```toml
[mcp]
enabled = true
review_profile = "default"
max_tool_rounds = 5

[mcp.servers.local_docs]
transport = "stdio"
command = "uvx"
args = ["example-mcp-server"]

[mcp.servers.remote_docs]
transport = "streamable_http"
url = "https://mcp.example.com/mcp"
headers_env = "LINGCHU_MCP_HEADERS_JSON"
allow_private_network = false
```

| Field | Default | Notes |
| --- | --- | --- |
| `enabled` | `false` | Master toggle for MCP discovery and execution |
| `review_profile` | `"default"` | Reserved for the legacy review profile name (kept for compatibility) |
| `max_tool_rounds` | `5` | Maximum agent rounds; must be between 1 and 5 |
| `[mcp.servers.<name>]` | `{}` | Subtable of MCP server definitions consumed by `MCPRuntime` |

Each `[mcp.servers.<name>]` entry is a `MCPServerDef`:

| Field | Default | Notes |
| --- | --- | --- |
| `transport` | required | One of `stdio`, `streamable_http` |
| `command` | `None` | Required for `stdio` transport |
| `args` | `()` | Tuple of arguments for `stdio` transport |
| `url` | `None` | Required for `streamable_http` transport |
| `headers_env` | `None` | Environment variable name holding a JSON headers object for HTTP transport |
| `allow_private_network` | `false` | Informational flag; HTTP egress policy is enforced downstream |

`MCPRuntime` owns one `pydantic_ai.mcp.MCPToolset` per configured server,
constructed lazily on first access through `_build_toolset()`. Each toolset
wraps a `fastmcp.client.Client` with the chosen `StdioTransport` or
`StreamableHttpTransport`. Only MCP Tools are exposed. Resources, prompts,
sampling, and legacy SSE are not supported. Model-facing names use
`<server>.<tool>`.

`MCPAgentRuntime.respond()` delegates the multi-round tool-calling loop to a
`pydantic_ai.Agent` configured with the authorized `MCPToolset`s. Pydantic
AI's native agent loop owns tool execution; the legacy project-side
multi-round orchestration, LLM-based review step, and confirmation flow have
been removed. The `decision` field on `MCPToolCallOutcome` is therefore
always `None`. The `confirmation_manager` parameter is retained on
`MCPAgentRuntime.__init__` so existing call sites continue to compile, but it
is not used.

Before any agent run, the existing identity-group system grants the highest
applicable MCP permission through `PermissionResolver`. Any non-None
permission level grants access to all configured MCP servers; `None` raises
`MCPAgentPermissionError`. If the agent run itself raises, `MCPAgentRuntime`
falls back to a plain `LLMRuntime.respond()` call without MCP context so the
caller still receives a stable `LLMResponse`.

MCP metadata and results are always treated as bounded untrusted data.

### Bounded immutable data

`security.py` enforces bounded, immutable, JSON-like data:

- `freeze_value()` deep-copies supported values into `MappingProxyType` / `tuple` containers with `MAX_NESTING_DEPTH = 8`, `MAX_COLLECTION_ITEMS = 100`, cycle detection, and rejection of non-string mapping keys.
- `thaw_value()` copies frozen values back into mutable `dict` / `list` for SDK calls.
- `sanitize_message()` strips control, separator, and bidi-override characters and redacts `Bearer`/`Basic` authorization values and credential-like assignments before returning bounded public exception text.
- `LLMProfile.__repr__` never renders `api_key` contents.

## Lifecycle and hot reload

A single managed `LLMRuntime` instance is held by `_managed_state` in `runtime.py` and protected by `_managed_runtime_lock` plus a `_LifecycleCoordinator` that serializes lifecycle work across threads and event loops.

| Function | Purpose |
| --- | --- |
| `get_llm_runtime()` | Return the process runtime, constructing it lazily on first access |
| `initialize_llm_runtime()` | Initialize once, serialized with reload and shutdown |
| `reload_llm_runtime()` | Publish a validated candidate, then close the previous runtime |
| `shutdown_llm_runtime()` | Detach and close the process runtime |
| `reload_mcp_agent_runtime()` | Atomically publish validated MCP configuration and close old toolsets |
| `shutdown_mcp_agent_runtime()` | Close MCP toolsets and detach the MCP Agent runtime |

### Hot reload semantics

`reload_llm_runtime()` follows a strict sequence so a failed reload never breaks the running bot:

1. Acquire the lifecycle coordinator ticket (serialized with init/shutdown).
2. Build a candidate runtime with `next_generation = current + 1` through `_build_managed_runtime()`. This calls `load_llm_runtime_config()` and constructs the `LLMRuntime` without publishing it, so configuration validation errors surface here.
3. Publish the candidate by swapping `_managed_state.runtime` and incrementing `_managed_state.generation`.
4. Call `invalidate_capability_cache()` so the next probe re-evaluates the new model string.
5. Close the previous runtime through `_finish_cleanup_before_cancellation()`, which keeps lifecycle serialization until owned cleanup finishes and propagates cancellation only after cleanup completes.

A close failure is propagated after the swap. The new generation remains published because rolling back to a partially closed runtime is unsafe. Profiles and agents are cached per `(name, generation, api_key fingerprint)`, so in-flight calls on the old runtime continue to resolve their own agents until the old runtime is closed. Agents own no explicit `close()` method, so cleanup simply clears the cached profile and agent dictionaries.

### Shutdown

`shutdown_llm_runtime()` sets `shutting_down = True`, detaches the runtime, and clears every owned profile and agent once, continuing after individual failures. `get_llm_runtime()` raises `_RuntimeClosingError` once shutdown has started.

<Aside title="Optional at startup">

`start/startup.py` resolves the localstore `llm.toml` path without creating it and wraps `initialize_llm_runtime()` in a try/except, so configuration or `pydantic-ai` dependency failures never prevent non-AI bot services from starting.

</Aside>
